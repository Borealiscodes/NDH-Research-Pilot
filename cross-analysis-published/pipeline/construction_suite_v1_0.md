# **1. Purpose**

The **Construction Suite v1.0** defines the *mechanical procedures* for generating publication‑ready artifacts within the NDH‑Research‑Pilot humane‑world constellation.  
It implements the governance rules defined in:

- **Zenodo Publishing Pipeline v1.0**  
- **Publication Sequencing & Quality Control v1.0**  

This Suite ensures:

- identity block correctness  
- provenance footer correctness  
- rendering consistency  
- citation ontology alignment  
- altitude compliance  
- versioning correctness  
- folder placement correctness  
- Omnibus compatibility  
- Zenodo readiness  

It is the **execution layer** of the publication lane.

---

# **2. Construction Workflow Overview**

The Construction Suite executes the following workflow:

```
draft → structural preparation → identity block insertion →
provenance footer insertion → citation alignment →
rendering normalization → versioning → publication-ready →
lane placement → omnibus integration → zenodo deposition
```

Each step is mandatory.

---

# **3. Artifact Preparation Stage**

Before construction begins, the artifact must be:

- conceptually complete  
- altitude‑safe  
- non‑activating  
- lineage‑safe  
- structurally scoped  

Artifacts failing these criteria return to drafting.

Artifacts passing move to **structural preparation**.

---

# **4. Identity Block Construction**

Every publication‑ready artifact receives a standardized identity block.

### **4.1 Required Fields**
- title  
- artifact name  
- version  
- altitude  
- lane  
- sealed status  
- canonical permalink  
- provenance anchors  
- maintainer  
- timestamp  

### **4.2 Construction Procedure**
1. Generate canonical artifact name.  
2. Assign version according to PSQC rules.  
3. Insert altitude declaration.  
4. Insert lane declaration.  
5. Insert provenance anchors.  
6. Insert canonical permalink.  
7. Insert timestamp (ISO 8601).  

Identity block must appear at the top of the file.

---

# **5. Provenance Footer Construction**

Every artifact ends with a standardized provenance footer.

### **5.1 Required Fields**
- artifact name  
- lane  
- altitude  
- status  
- purpose  
- anchors  
- maintainer  
- location  
- timestamp  

### **5.2 Construction Procedure**
1. Generate purpose statement.  
2. Insert altitude declaration.  
3. Insert lineage‑safe status.  
4. Insert anchors.  
5. Insert timestamp.  

Footer must appear at the bottom of the file.

# **6. Rendering Normalization**

Rendering normalization ensures Omnibus and Zenodo compatibility.

### **6.1 Markdown Enforcement**
- no HTML  
- no LaTeX environments  
- no PDF embeds  
- no external formatting  

### **6.2 Section Hierarchy**
```
# Title
## Section
### Subsection
```

### **6.3 Geometry & Ontology Notation**
Use unified notation from:

- Geometry Basin  
- Holonomy Physics Basin  
- Tonal Spiral Geometry Basin  
- UDL Basin  
- SEAM Basin  
- Visual‑Domain Geometry Basin  

### **6.4 No conversational tone**
Publication‑ready artifacts must be academic.

Artifacts must reference:

- SCI‑80 lineage

Citation alignment ensures Omnibus consistency.

# **8. Versioning Assignment**

Versioning follows PSQC rules:

- **v1.0** — first stable publication  
- **v1.1** — minor corrections  
- **v2.0** — major revision  

Drafts use:

- **v1.0‑draft**  
- **v1.1‑draft**  

Only **v1.0+** enters the publication lane.
