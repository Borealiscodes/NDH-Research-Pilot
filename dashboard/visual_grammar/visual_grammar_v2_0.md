## ⭐ **2 — Purpose of Visual Grammar v2.0**

The grammar ensures:

- orb semantics are consistent across Dashboard modules  
- icon semantics are altitude‑safe and contributor‑friendly  
- expressive skins wrap RP artifacts without contamination  
- expressive geometry remains posture‑safe  
- JSON metadata maps cleanly to visual tokens  
- animations remain drift‑neutral and non‑recursive  
- expressive overlays remain governance‑safe  
- Dashboard visuals remain reversible and altitude‑neutral  

This grammar is the **visual operating system** of the Dashboard.

## ⭐ **3 — Orb Semantics (v2.0)**

Orbs now have **strict semantic definitions**.

| Orb | Meaning | Safety |
|------|---------|--------|
| 🟦 | Foundation / Base Layer | RP‑safe |
| 🟩 | Expressive Layer | posture‑safe |
| 🟪 | Stability / Diagnostic Layer | RP‑safe |
| 🟧 | Dashboard Interaction Layer | RP‑safe |
| ⚫ | Constellation Reference | restricted |
| 🔴 | Runtime / GPU | forbidden |

Rules:

- Orbs represent **state**, not logic.  
- Orbs must not encode activation geometry.  
- Orbs may appear in Dashboard UI but **never** in machine‑readable JSON.

---

## ⭐ **4 — Icon Semantics (v2.0)**

Icons are symbolic markers for Dashboard modules.

| Icon | Module |
|-------|---------|

| 🜂 | Bundles |

| 🜅 | GPU Planning |

Rules:

- Icons may appear in UI and documentation.  
- Icons must not encode ingestion rules.  
- Icons must not appear in JSON envelopes.

## ⭐ **5 — Expressive Geometry Envelope (v2.0)**

This defines how expressive skins wrap RP artifacts safely.

### Allowed expressive elements:
- soft corner rounding  
- lantern‑glow gradients  
- constellation sparkle accents  
- pastel neon header motifs  
- cold cosmic aurora overlays  
- micro‑animations (posture‑safe only)  

### Forbidden expressive elements:
- symbolic behavior  
- recursive geometry  
- narrative lift  
- altitude oscillation  
- governance contamination  

### Envelope Rule:
> Expressive geometry must always wrap RP artifacts **from the outside**, never embed inside governance structures.

---

## ⭐ **6 — Dashboard‑Safe Animation Rules (v2.0)**

Animations must be:

- <5° curvature  
- <300ms duration  
- non‑recursive  
- non‑symbolic  
- posture‑safe  
- ΔAltitude = 0  

Allowed:

- micro‑sparkle gradients  
- soft hover glows  
- gentle transitions  

Forbidden:

- pulsing altitude metaphors  
- recursive loops  
- symbolic morphs  
- constellation‑binding animations  

---

## ⭐ **7 — Machine‑Readable Visual Tokens (v2.0)**

JSON may reference visuals only through **tokens**, not icons or orbs.

Example:

```
"visual_token": "zen_kawaii_soft_glow_v2"
```

Rules:

- tokens must be posture‑safe  
- tokens must be non‑activating  
- tokens must not encode geometry  
- tokens must not encode altitude  
- tokens must not encode recursion  

---

## ⭐ **8 — Expressive‑Governance Boundary (v2.0)**

This is the core safety rule.

> Expressive layers may wrap governance layers, but governance layers may never wrap expressive layers.

This prevents:

- contamination  
- adjacency formation  
- altitude drift  
- expressive recursion  
- symbolic activation
