## ⭐ **0. Purpose**
This Omnibus establishes the **complete design‑ethos layer** for VM‑VEX.  
It consolidates all architectural stances, cognitive modes, altitude rules, primitive‑separation principles, and sequencing disciplines into a single, authoritative reference.

It replaces dual framings (e.g., “caution vs smartness”) with **non‑binary architectural orientations** that emphasize:

- structural foresight  
- altitude safety  
- sequencing discipline  
- primitive separation  
- cognitive clarity  
- trauma‑informed design  

This Omnibus governs all future design‑ethos documents.

---

# ⭐ **1. Ethos Taxonomy**

The VM‑VEX design ethos consists of **five architectural orientations**:

1. **Structural Alignment Ethos**  
2. **Altitude Governance Ethos**  
3. **Primitive Separation Ethos**  
4. **Sequencing Discipline Ethos**  
5. **Cognitive Mode Ethos**

These orientations replace dual framings and provide a unified architectural posture.

---

# ⭐ **2. Altitude Governance Ethos**

Altitude governs what visual primitives may appear in which layer:

```
A6  → static visibility
A7  → structured visibility
A8  → flow / continuity
A9  → integration / multi-domain
```

Design documents must remain in **A6/A7**, even when describing A8/A9.

### Ethos Principles

- Never introduce flow semantics in A6/A7.  
- Never introduce integration semantics in A6/A7.  
- Always seal a layer before ascending.  
- Always audit before introducing new primitives.

---

# ⭐ **3. Primitive Separation Ethos**

VM‑VEX uses three primitives:

```
ORB (●)     → state (A6/A7)
BAND (▬)    → flow (A8)
LATTICE (#) → integration (A9)
```

### Ethos Principles

- Orbs must remain static.  
- Bands must remain flow‑only.  
- Lattices must remain integration‑only.  
- Never mix primitives across altitude layers.  
- Never introduce band or lattice semantics into orb dashboards.  
- Never introduce orb semantics into band or lattice diagrams.

Primitive separation prevents activation adjacency and cognitive overload.

---

# ⭐ **4. Sequencing Discipline Ethos**

VM‑VEX requires strict sequencing:

```
STEP 1 → Normal Dashboards (HR + MR)
STEP 2 → Orb Dashboards (HR)
STEP 3 → Orb Consolidated Snapshot
STEP 4 → Visual Architecture Document
STEP 5 → Audit Logic
STEP 6 → Seal A6/A7
STEP 7 → Authorize A8 Band Layer
```

### Ethos Principles

- Documentation precedes artifacts.  
- Architecture precedes flow.  
- Audit precedes altitude transitions.  
- Sequencing is structural, not optional.

---

# ⭐ **5. Structural Alignment Ethos**

Structural alignment is the core architectural stance of VM‑VEX.

### Ethos Principles

- Act early, not reactively.  
- Anticipate altitude consequences.  
- Align primitives before generating artifacts.  
- Maintain stability ecology across layers.  
- Reduce cognitive load through structural clarity.

This ethos replaces “smartness vs caution” with a **single architectural posture**.
