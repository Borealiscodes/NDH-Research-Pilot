## 1 — Purpose

**Series V** maps how the major architectural clusters in the Borealiscodes constellation relate to each other:

- NDH cognitive‑architecture cluster  
- Spectral runtime / geometry cluster  
- Zen‑AI / expressive / constitutional cluster  
- Governance / treaty / ecology cluster  
- Sandbox / prototype cluster  

It focuses on **relationships**, not activation: who leans on whom, who stabilizes whom, who expresses whom.

## 3 — Relationship map (high‑level)

- **NDH Core ↔ Spectral Runtime:**  
  **Label:** Architecture ↔ Engine  
  **Relation:** NDH core defines cognitive architecture; spectral runtimes implement geometry and execution surfaces.

- **NDH Core ↔ Zen‑AI / Expressive:**  
  **Label:** Architecture ↔ Posture  
  **Relation:** NDH core defines structure; Zen‑AI defines posture, ergonomics, humane interaction, and constitutional membranes.

- **Spectral Runtime ↔ Zen‑AI / Constitutional:**  
  **Label:** Engine ↔ Constitutional Interface  
  **Relation:** spectral engines provide geometry; Zen‑AI (with RESM + Rendering Ladder + Dream‑Lane) governs rendering, sovereignty, and traversal.   

- **NDH Core ↔ Governance / Treaties:**  
  **Label:** Architecture ↔ Law  
  **Relation:** NDH core expresses systems; governance repos express charters, treaties, and ecological metaphors that constrain and narrate those systems.

- **Expressive / Constitutional ↔ Governance:**  
  **Label:** Membrane ↔ Charter  
  **Relation:** Zen‑AI and Dream‑Lane provide humane, reversible constitutional surfaces; governance repos provide formal charters and treaty logic.

- **Sandbox ↔ All Clusters:**  
  **Label:** Prototype ↔ Ecosystem  
  **Relation:** sandbox repos test ideas before they enter NDH core, spectral engines, or expressive/constitutional layers.
