# ⭐ **1 — Purpose of Harm Topology Rendering Grammar**

Harm topology rendering answers one question:

> **How do we *draw* harm-phase geometry in a way that is structurally correct,  
> rate‑accurate, and topology‑safe?**

It does **not**:

- interpret harm  
- assign meaning  
- evaluate ethics  
- activate sealed layers  
- invoke governance altitude  
- use expressive geometry  

It is purely **structural rendering logic**.

---

# ⭐ **2 — Harm‑Phase Rendering Primitives**

Rendering uses seven primitives:

### **1 — Node**  
Represents a harm‑phase object:  
[L], [A], [E], [D], [T], [C], [X], [R]

### **2 — Edge**  
Represents a harm‑phase transition.

### **3 — Rate Vector**  
Represents rate magnitude and direction.

### **4 — Curvature Marker**  
Represents trajectory curvature.

### **5 — Collapse Marker**  
Represents collapse thresholds.

### **6 — Residual Basin**  
Represents long‑tail harm.

### **7 — Recovery Surface**  
Represents stabilization geometry.

These primitives are **non‑expressive** and **topology‑safe**.

---

# ⭐ **3 — Harm‑Phase Rendering Surfaces**

Rendering uses four surfaces:

### **Structural Surface (S₁)**  
Topology, shape, adjacency.

### **Temporal Surface (S₂)**  
Rate, acceleration, dissipation.

### **Residual Surface (S₃)**  
Long‑tail decay, basin geometry.

### **Recovery Surface (S₄)**  
Return‑path stability.

Each surface is rendered independently and then composited.

---

# ⭐ **4 — Rendering Rules for Harm‑Phase Objects**

Each harm‑phase object has a rendering rule:

### **L (Latent)**  
- low opacity  
- low curvature  
- minimal rate vectors  

### **A (Activation)**  
- rising rate vectors  
- increasing opacity  
- slight curvature  

### **E (Escalation)**  
- strong rate vectors  
- high curvature  
- instability markers  

### **D (Damage)**  
- topology deformation  
- structural stress lines  
- collapse markers begin  

### **T (Tension)**  
- load-bearing geometry  
- high stress density  
- collapse threshold visible  

### **C (Collapse)**  
- topology failure  
- dissipation onset  
- basin formation  

### **X (Residual)**  
- long-tail basin  
- slow decay vectors  
- low curvature  

### **R (Recovery)**  
- stabilization surface  
- return-path geometry  
- dissipation closure  

These rules ensure **consistent rendering across harm-phase space**.

---

# ⭐ **5 — Rendering Rules for Harm‑Phase Transitions**

Transitions are rendered using:

### **Directional Edges**  
L → A → E → D → T → C → X → R

### **Rate Vector Encoding**  
Magnitude = vector length  
Direction = vector orientation  
Volatility = vector jitter  

### **Curvature Encoding**  
Curvature = trajectory bending  
High curvature = instability  
Low curvature = stabilization  

### **Collapse Encoding**  
Collapse threshold = red boundary  
Collapse event = topology break  

### **Residual Encoding**  
Residual basin = concave region  

### **Recovery Encoding**  
Recovery surface = convex region  

---

# ⭐ **6 — Rendering Rules for Harm‑Phase Rates**

Rates are rendered as:

### **\(\dot{A}\)** — Activation Rate  
Upward vectors, increasing opacity.

### **\(\dot{E}\)** — Escalation Rate  
Accelerating vectors, curvature spikes.

### **\(\dot{D}\)** — Damage Rate  
Stress lines, topology deformation.

### **\(\dot{T}\)** — Tension Rate  
Load-bearing density, collapse markers.

### **\(\dot{C}\)** — Collapse Rate  
Topology break, dissipation onset.

### **\(\dot{X}\)** — Residual Rate  
Slow decay vectors, basin geometry.

### **\(\dot{R}\)** — Recovery Rate  
Stabilization vectors, convex surfaces.

---

# ⭐ **7 — Rendering Rules for Harm‑Phase Trajectories**

Trajectories are rendered using:

### **Trajectory Line**  
Primary path through harm-phase space.

### **Trajectory Curvature**  
Represents instability or stabilization.

### **Trajectory Volatility**  
Represents rate jitter.

### **Trajectory Collapse Points**  
Represent topology failure.

### **Trajectory Recovery Points**  
Represent stabilization.
