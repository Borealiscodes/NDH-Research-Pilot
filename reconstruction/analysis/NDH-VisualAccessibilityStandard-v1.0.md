# 📘 **NDH‑VisualAccessibilityStandard‑v1.0.md**  
### *NDH‑RESEARCH‑PILOT • Reconstruction / Analysis Lane*  
### *Non‑Activating • Documentation‑Only • Altitude‑Safe*

---

## ⭐ 1 — Purpose  
This standard defines how NDH‑RESEARCH‑PILOT documentation may safely use:

- **colored orbs**  
- **ASCII icons**  
- **machine‑readable JSON**  

without violating altitude, lane separation, or stability‑ecology constraints.

It ensures contributors, reviewers, and public‑safe readers can navigate complex sequencing documents without interacting with VM‑VEX or runtime systems.

---

## ⭐ 2 — The Three‑Layer Documentation Model

```
+-----------------------------------------------------------+
|           NDH SAFE DOCUMENTATION ACCESSIBILITY            |
+----------------------+------------------------------------+
| Layer 1: Visual      | Colored Orbs (public-safe)         |
|                      | High-accessibility visuals         |
+----------------------+------------------------------------+
| Layer 2: Symbolic    | Icons (🜁 🜂 🜃 🜄 🜅 🜆)               |
|                      | ASCII diagrams                     |
|                      | Contributor-facing clarity         |
+----------------------+------------------------------------+
| Layer 3: Machine     | JSON envelopes                     |
|                      | Ingestion grammar                  |
|                      | Virtual memory maps                |
+----------------------+------------------------------------+
| VM-VEX Uses          | Machine Layer ONLY                 |
+-----------------------------------------------------------+
```

Each layer is **strictly non‑activating** and **lane‑safe**.

---

## ⭐ 3 — Layer Definitions

### 🟢 **Layer 1 — Colored Orb Version (Visual Layer)**  
Used for:

- public‑safe documentation  
- contributor onboarding  
- visual clarity  
- phase separation  

Rules:

- Orbs represent **phases only**, not logic.  
- Orbs must not encode runtime triggers.  
- Orbs must not encode ingestion rules.  
- Orbs must not appear in machine‑readable artifacts.

Example mapping:

| Phase | Orb |
|-------|-----|
| Foundations | 🟦 |
| Bundle Construction | 🟩 |
| VM‑VEX Stabilization | 🟪 |
| VM‑VEX Internal Components | 🟧 |
| GPU Planning | 🔴 (forbidden) |
| CONSTELLATION | ⚫ (restricted) |

---

### 🜁 **Layer 2 — Icon Version (Symbolic Layer)**  
Used for:

- NDH‑internal contributors  
- ASCII‑safe documentation  
- reconstruction lane artifacts  
- sequencing clarity  

Icons:

- 🜁 Foundations  
- 🜂 Bundle  
- 🜃 Stabilization  
- 🜄 VM‑VEX Internal  
- 🜅 GPU Planning  
- 🜆 CONSTELLATION  

Rules:

- Icons may appear in any human‑readable documentation.  
- Icons must not appear in machine‑readable JSON.  
- Icons must not encode activation geometry.

---

### 📄 **Layer 3 — Machine‑Readable Version (VM‑VEX Layer)**  
Used for:

- ingestion  
- validation  
- altitude enforcement  
- recursion ceilings  
- safety flags  
- VM‑VEX internal logic  

Rules:

- Must be JSON or equivalent structured format.  
- Must contain explicit fields.  
- Must not contain icons or colored orbs.  
- Must not contain prose.  
- Must not contain diagrams.

Machine‑readable versions are required for:

- Runtime Envelope  
- Ingestion Grammar  
- Virtual Memory Map  
- Stability‑Ecology Hooks  
- Bundle Interface  
- Pre‑Runtime Sequencer  

---

## ⭐ 4 — Safety Constraints

### Altitude Safety  
All visual elements must remain within:

\[
A5 \leq A \leq A7
\]

### Lane Safety  
Visual elements may appear only in:

- analysis lane  
- governance‑adjacent lane  

### Activation Safety  
Visual elements must not:

- encode runtime logic  
- encode ingestion rules  
- encode binding geometry  
- encode recursion triggers  

### VM‑VEX Safety  
VM‑VEX must **never** parse:

- colored orbs  
- icons  
- ASCII diagrams  

Only machine‑readable JSON is ingested.
